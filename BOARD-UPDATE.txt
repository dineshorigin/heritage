PALLANGUZHI v3.18.0 — PROPORTIONAL BOARD VIEW

The portrait board was already limited by available screen height. With the complete original board visible, its aspect ratio necessarily leaves side space on this tall device. Filling both width and height simultaneously would distort or crop it.

Changes:
- More room for the default full-board view: smaller portrait header, guide row and Tools footer. The guide has fixed height/overflow, preventing messages from shrinking the board.
- Tools > Bigger board uniformly enlarges both board dimensions. The enlarged board sits in a native scrollable viewport: pan to see both ends. Tools > Whole board returns to the complete board. No pit/board stretching, repainting, separate axis scaling, or permanent cropping.
- The view preference is saved locally and does not affect the opponent's device or game rules.
- Existing normalized cup centres and dimensions are retained, so artwork and hit targets use one scale. Scrolling invalidates cached screen positions for hand/seed destinations.
- Enlargement is capped at 1.85 times the full-board fit. On a representative 393x630 CSS-pixel stage the portrait board width grows from about 232px to 381px; its added length is accessible by scrolling. This is sizing math, not a browser screenshot measurement.
- Board-size switching waits for the current move to finish. Native scrolling remains available in enlarged view. There is no automatic camera tracking; pan manually. Use Whole board for an unobstructed view of every move.
- Fit remains the existing fullscreen action, which can reclaim browser chrome when supported. No layout can reclaim the OS/browser bars without browser permission/fullscreen support.

Validation:
55 automated tests passed, including uniform scaling at six portrait/landscape stage sizes, all fourteen cup targets and full scroll bounds. Syntax, balanced HTML, unique IDs and literal element references passed. Android source sync passed; no APK built. Archive integrity passed. Game rules are unchanged from v3.17; the existing 800-match simulation result is retained as historical engine evidence.

Browser/device visual verification is outstanding. Automatic approval review previously rejected browser inspection due to the session usage limit. No alternate browser was used to bypass it. Normal-view size gain, enlarged touch panning and animation appearance while panning require manual checks. No full release certification, GitHub commit or live deployment is claimed.
